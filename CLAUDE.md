# Bramblewood Arena: working rules

Web card game (creature cards, lanes, maps, raids). One page built from many scripts.
- Live: https://bramblewood-arena.vercel.app (pushing `main` deploys it)
- Repo: `herougan/bramblewood-arena-game` · Hub: https://claude.ai/artifact/45sGJuWwy9T6ocC1D4K99J · Supabase project `xjctfwobcsyiztecutrb`
- Claude Project "Web-Battle-Game" holds design docs; `claude/START-HERE.md` there explains how a new chat sees the game.

## Hard rules
- Live database writes (Supabase) only after the owner says "apply it" for that change. Read-only SQL is fine. Proposed SQL goes in `supabase/proposed/`.
- Never buy anything (PixelLab, Supabase, Vercel, NightCafe plans, credits, domains). Never print tokens, create accounts or enter passwords.
- The owner's email identifies them only; never send it anywhere.
- Never use the watermarked stock image. Art prompts: always a background; avoid "no clothes", weapon words, "spiked", "studded", "monitor", "sperm", "corpse".
- Never claim a check passed that you did not run. "Cached" (passed before on identical inputs) is reported as cached.

## Build, test, merge, release
- Build: `python3 assemble_arena.py && mv bramblewood-arena.html index.html`. Never edit `index.html`, `assets/lang/*.js` or `docs/game-texts.xlsx` by hand.
- Tests (list in `tests/run-all.sh`, run with `tests/run.js`):
  - `node tests/run.js --smoke`: about a minute; run first.
  - `node tests/run.js --only '<regex>'`: the package's own and directly affected tests.
  - `node tests/run.js`: everything, skipping tests that passed on identical inputs.
  - `node tests/run.js --full --e2e`: release only.
- Merge a package branch: `bash tools/merge/merge_pkg.sh <branch>`. It resolves generated files, the language packs, the CHANGELOG and run-all.sh, then rebuilds. It stops on any other conflict. Never union `.js` files.
- Release (push and deploy, then republish the hub): once per finished batch, never per package. Steps: `docs/workflows/release.md`.

## Working style
- Search before reading: `docs/code-map.md`, then `grep -n`. `arena_app.js` is about 51k lines; read only the region you need.
- Batch work of the same kind. Run agents in parallel only if they touch different files. Most packages touch `arena_app.js` and the 12 language packs, so run those in sequence.
- Agent briefs: name the workflow file, the exact items, and the files the agent may touch. Don't paste these rules into the brief.
- Agent worktrees start from GitHub's `main`. While a batch is unpushed, the brief starts with "run `git merge main` first", or the agent works on old code.
- Model choice:
  - the top model for engine design, balance and final review;
  - a cheaper model for UI from a clear spec, translations, docs and data edits;
  - the Explore agent for lookups.
- Code comments: a date and the reason, in the existing style. Each package adds a short entry at the top of `docs/CHANGELOG.md`.
- Owner-facing reports: short, player-visible changes first, then decisions the owner needs to make. New owner calls go into `docs/decisions.json`.
- Project docs: write only canonical or decision docs there. Every write clears the cache for every chat in the Project.
