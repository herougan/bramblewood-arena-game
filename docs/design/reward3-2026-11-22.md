# REWARD3 (2026-11-22): Reward picks, General drops, Free drops, counts

Owner 22:41, items 3, 4, 8, 9. Admin only (the player sees the effect: what drops where). Code: the `REWARD3` block before `UI37_KEY` in `arena_app.js` (`rw3*`), the state next to `PACKSET_KEY` (`rw3State`, `rw3IsReward`, `rw3IsBaby`, `rw3Want`), CSS in `arena_template.html` (`.rw3-*`).

## What the owner sees
- **Map cards window** (main maps and side maps): every Yes card has a **Reward** tick, a fight list (the fight that gives it) and **x N**. At most **2 Reward cards per map**; a side map has its own 2 (same rule, it makes sense there: a side map has 3-6 fights). A third tick is refused with a toast. Turning a card to No removes its Reward.
- Right-click a tile: the same three controls in a small menu. The Pack editor's All cards panels have the same entry in their right-click menu (the map comes from the card's map move or its first list).
- **Reward pill** on the card everywhere it shows (Map cards, the Skirmish rewards section, the Pack editor panels). A Reward card shows no Pack pill: it is in no pack.
- **Labels** (new): swords N = skirmish decks using the card; sparkles N = New! skills it carries (skills no earlier main map shows); faction (Base / Hummingbirds / Otters); target + code = already a reward at that fight. Rarity, budget %, Pack N, Baby, Starter were already on the tile.
- **Free drops** section (Map 0 window and the tutorial map window): every Baby card, every starter-deck card (STARTER_CFG_DEFAULT, TUTORIAL_CFG_DEFAULT, the live config, `starterDeckParts` of both sides) and the T-1 / T-2 cards. Each shows where it drops for free (a fight code, General drop, a pack, Nest / quest) or a red **No free drop** with **Add as reward**. The add goes to Map 0 outside the 2 picks and gets an auto fight; its controls (fight, x N, untick) show on the tile.

## Data shape
`rw3State = {r: {mapKey: [ids]}, f: {mapKey: [ids]}, node: {id: 'mapId:nodeKey'}, n: {id: copies}, localAt}`. `r` = ticked picks (max 2 a map), `f` = Free drops adds. Saved in localStorage `bw_reward3_v1` and the admin row `__cfg:reward3` (`rw3Publish`, written when the admin clicks; `applyCloudReward3` reads it, newer side wins, as the map picks do). No SQL.

## How the game reads it
- `basicPackTierOf`: a Reward card and a General Baby card return 0 (no pack pool, no pack extras). T-1 / T-2-only base cards were already 0 (the tutorial list is skipped by `packIndexBuild`).
- `cardObtainableFrom`: a Reward card, and a General Baby card with a count above 0, are `skirmish` (so not "unattainable").
- Fight: `rw3NodeOf(id)` = the picked fight, else spread over the map's skirmishes by the card's place in the map's list (2 picks on a 4-fight map: fights 2 and 4). `nodeFirstClearCardIds` adds `rw3NodeIds`, so the first clear, Clear map, the First Clear box and the Skirmish rewards section all see it.
- **General drops**: a Baby card whose source is a pack, base or none (`rw3IsBaby`; fight, nest and quest Babies keep their own giver) joins `skirmishDropPick`'s pool while the copies owned are under its count (starter-rarity Babies count as Common). Every fight win rolls that pool as before; no new chance was added.
- **Count x N** (default 1, 0 = never): `rw3Want` = N capped by the rarity copy cap. The first clear gives 1 copy; `skirmishOwnDropIds` drops a Reward card on a repeat win only while `copiesOwned < rw3Want` (the existing 10% own-card roll, `rollCardDrop`), so a x3 card gives 1 + 2 repeats. A General drop is in the pool only while `copiesOwned < rw3Want`.

## Limits
- A General Baby drop is a chance (the fight's 1-9% pick across a rarity band), not a guarantee; a Free drops flag only says nothing gives the card. Add as reward guarantees one copy on Map 0's first clears.
- The tutorial's own reward is a random faction draw, so it is not counted as a free source.
- Fight lists edit through the tile controls; the older node rewards editor still edits only the card-source exclusives.
