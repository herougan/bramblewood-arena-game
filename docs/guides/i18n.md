# Texts and translations cheat sheet (2026-11-11, GUIDE1)

English is the source. 12 languages, always in this order in scripts: `fr de es it pt tl ta id zh-Hans zh-Hant ja ko`. (`docs/i18n.md` is older: card names do translate now.)

## Where text lives
| What | Source | Translations |
|---|---|---|
| Toasts, dialogs, coach and tutorial tips, results, skill texts, most UI labels | `bramblewood-texts.js` `TEXT` table (`"ui.<pkg>-<name>": "English"`), read with `TX('key', {n})` | `lang/<code>.json`, keyed by the English text |
| Card names | `canonical/cards.json` `name` | `lang/cards/<code>.json` (`tools/i18n_cards.py` reports gaps) |
| Literal English left in `arena_app.js` (labels in templates, titles, NPC lines, errands) and card flavour | the source itself | `lang/ui/<code>.json`, harvested by `tools/i18n_ui.py` |
| Owner-editable copy of all texts | `docs/game-texts.xlsx` (generated: `python3 tools/text/export_texts.py`; owner edits come back with `tools/text/import_texts.py FILE.xlsx`) | |

The build merges `lang/ui`, then `lang/cards`, then `lang/<code>.json` (later wins) into `assets/lang/<code>.js`.

## How it reaches the screen
- `TX()` returns English with `{placeholders}` filled. Code that compares strings still sees English.
- The page translator (`bramblewood-i18n.js`, `i18`) swaps every rendered text node, `title`, `aria-label`, `placeholder` and `data-tip` whose English is a pack key. Leading emoji and symbols are ignored and kept. Keys with `{x}` match as templates, and numbers are formatted per language.
- Skipped: anything under `[translate="no"]`, `.no-i18n`, inputs, text areas.
- A sentence built in code with numbers or names: `TX('key', {n})` with the number as a placeholder, never one key per number (`python3 tools/text/templatize_numbers.py --check`).
- Text cut up by inline tags (`<b>`, `<i>`) reaches the page in pieces and will not match: make it one `TX` key with placeholders.
- In the browser console, `BramblewoodI18n.misses()` lists English seen on screen with no translation.

## Add or change a text (the usual package step)
1. Add keys to `TEXT` and rows to the 12 `lang/<code>.json` files with one dated script, `tools/i18n_<date>_<pkg>.py`: copy the newest one (`ls -t tools/i18n_2026_11*.py | head -1`), replace its `NEW = {...}` table (`'ui.key': T('English', fr, de, es, it, pt, tl, ta, id, zh-Hans, zh-Hant, ja, ko)`), run it. It is safe to run twice.
2. Changing an English text changes its pack key: add the new English to all 12 packs (old rows can stay until `tools/i18n_ui.py --write` prunes `lang/ui`).
3. If you used `python3 tools/text/keyify.py`, check `git diff bramblewood-texts.js`: it deletes keys the game builds by name (`'ui.tf-' + name`, `'ui.fog-row-' + k`). Restore any it dropped.
4. `python3 tools/text/export_texts.py` (refreshes the spreadsheet), then build.
5. Tests: `node tests/run.js --only 'i18n|game-texts'` (`i18n-ui-2026-10-18` is in the smoke set and fails on stale `lang/ui` rows or a lost placeholder). Browser check: `python3 tests/e2e/i18n.py`.

## Translation rules
- Keep every `{placeholder}` exactly; keep emoji; no new placeholders. English plural endings `{s}` may be dropped.
- As short as the English or shorter: German, French and Tamil run long and break tight chips and card scrolls.
- Game words stay consistent across a language: reuse the existing pack's word for Bramble, Lumber, Wait, Ready, Shield, Forge, skirmish (search the pack: `jq -r '.["Lumber"]' lang/de.json`).
- Ranks are an emblem, never words; rank letters are not translated text.
- Drafts: French, German, Spanish, Italian, Portuguese, Indonesian and Chinese are close to final; Tagalog, Tamil, Japanese and Korean need a native read before launch (`tools/i18n_core.py` header).
- Write English for players first (`docs/workflows/code-quality.md`, in-game copy): a shorter English text is 12 shorter translations.

## Merging
`tools/merge/merge_pkg.sh` merges `lang/*.json` and `lang/ui/*.json` 3-way by key (`tools/merge/merge_lang.py`) and keys both sides appended to `TEXT` (`tools/merge/union_texts.py`). Two packages adding the same key with different English still need a human.

## Cheap checks
- One key's translations: `for f in lang/*.json; do printf '%s ' "$f"; jq -r --arg k "English text" '.[$k] // "MISSING"' "$f"; done`
- Never open a whole pack (`lang/de.json` 420 KB, `lang/ui/de.json` 516 KB) or `bramblewood-texts.js` (270 KB): grep the key.
